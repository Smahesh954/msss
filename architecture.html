Detailed AWS System Architecture, Async Event-Driven Flow, CI/CD Pipeline & Core Concepts

Objective

A background service that records/ingests meeting audio, transcribes it in real time, and uses RAG to answer questions about past meetings or auto-generate action items and summaries.

AWS Architecture & Services Specification

AWS Service Purpose in this Project Decoupled Architecture Implementation
Amazon Transcribe Speech-to-text with speaker diarization Identifies separate speakers (Alice, Bob, Charlie) in streaming chunks
Amazon S3 Store raw audio + generated transcripts Emits ObjectCreated events; lifecycle policy archives audio to Glacier
AWS Lambda Trigger transcription on upload, post-process transcript Runs asynchronous micro-tasks triggered by EventBridge rules
Amazon Bedrock Summarization, action-item extraction, RAG Q&A over past meetings Leverages Claude 3.5 with JSON schema enforcement
OpenSearch Serverless / Bedrock KB Vector store of meeting transcripts Indexes time-ordered chunks with speaker attribution embeddings
Amazon EventBridge Orchestrate the async pipeline (upload → transcribe → summarize → index) Replaces synchronous request-response with pub/sub event rules
Amazon DynamoDB Meeting metadata, action items, calendar links Single-table design: PK = MeetingId, SK = ActionItemId / TurnId
Amazon SNS / SES Email meeting summaries to participants after processing Dispatches HTML formatted executive summary within 60s of meeting end

Advanced Concepts You Must Learn

  • ✓
    Real-time/streaming audio transcription pipelines: Handling chunked audio buffers over WebSocket / HTTP2 bi-directional streams.
  • ✓
    Speaker diarization (identifying who said what): Clustering audio turns by acoustic biometric fingerprints to assign speaker identifiers.
  • ✓
    Chunking transcripts for RAG while preserving speaker/timestamp context: Avoiding naive token slicing which splits sentences across speakers.
  • ✓
    Action-item and decision extraction via structured LLM output: Using Bedrock tool use / JSON mode to output validated task schemas.
  • ✓
    Background/async processing architecture: Event-driven pipeline decoupled from UI request-response to prevent timeouts.

CI/CD Pipeline & Cutover Requirements

  • ⚡
    CI pipeline with sample audio fixtures: Regression-test the transcription-to-summary pipeline on every git push.
  • ⚡
    Infrastructure as Code (IaC): AWS CDK / Terraform definitions for S3 Event → Lambda → Transcribe → Bedrock.
  • 🛡️
    Dead-letter queues (DLQ) tested in CI: Ensures corrupt audio files or failed transcription jobs trigger SQS DLQ alerts, not silent drops.
  • 🚀
    Staged deploys with shadow pipeline: Processes real meetings in parallel without sending emails to validate summary accuracy before cutover.
