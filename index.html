AWS Architecture & CI/CD Pipeline

Deep dive into AWS services, asynchronous event flows, dead-letter queues, and CI/CD fixtures.

Objective

A background service that records/ingests meeting audio, transcribes it in real time, and uses RAG to answer questions about past meetings or auto-generate action items and summaries.

Advanced Concepts Implemented

🎙️ Streaming Audio Pipeline

  • Real-time WebSocket audio streaming to Amazon Transcribe
  • Opus/WAV 16kHz chunking with low latency buffers
  • Graceful handling of pauses and background silence

👥 Speaker Diarization

  • Identify distinct speaker voices (Alice, Bob, Charlie)
  • Assign start/end timestamps and confidence scores
  • Maintain speaker attribution across pauses

🧩 Preserved Context Chunking

  • Chunks format: [timestamp] Speaker: utterance
  • Preserves conversational boundaries for accurate RAG retrieval
  • Embeddings stored in OpenSearch Serverless vector index

📋 Structured LLM Output

  • Prompting Amazon Bedrock Claude 3.5 with strict JSON schemas
  • Extraction of Action Items with task, assignee, and priority
  • Syncing decisions directly into Amazon DynamoDB

AWS Architecture & Services Mapping

AWS Service Purpose in this Project
Amazon Transcribe Speech-to-text with speaker diarization
Amazon S3 Store raw audio + generated transcripts
AWS Lambda Trigger transcription on upload, post-process transcript
Amazon Bedrock Summarization, action-item extraction, RAG Q&A over past meetings
OpenSearch Serverless / Bedrock Knowledge Base Vector store of meeting transcripts
EventBridge Orchestrate the async pipeline (upload → transcribe → summarize → index)
DynamoDB Meeting metadata, action items, calendar links
SNS / SES Email meeting summaries to participants after processing

CI/CD Pipeline & Reliability Requirements

🧪 Regression Testing Fixtures

CI pipeline includes sample audio fixtures (WAV files of synthetic conversations) to regression-test the transcription-to-summary pipeline and verify action-item extraction accuracy.

🚨 Dead-Letter Queues (DLQ)

DLQ tested in CI to ensure failed transcription jobs (corrupted audio, timeout, quota limits) are retried 3 times, alerted via CloudWatch/SNS, and not silently dropped.

👥 Shadow Pipeline Deployment

Staged deploys with a shadow pipeline that processes real meetings without sending summaries, to validate transcription accuracy and RAG quality before final cutover.

Meeting Archive & Knowledge Base

Historical meetings indexed in OpenSearch Serverless with full dialogue turns and speaker timestamps.
